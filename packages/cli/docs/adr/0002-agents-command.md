# How `nativecn-cli agents` writes the Agent Kit

`nativecn-cli agents` (#57) writes or refreshes the Agent Kit in a project; `init` and `create` call the same `agents()` function for the agents the user chose.

The Rules (`packages/agent-kit/rules/`) and Skills (`skills/<name>/`) are **distributed from GitHub only** (#16), never inside the npm package. `agents` fetches them by a shallow sparse git checkout of Barun355/nativecn at the tag matching the CLI (`nativecn-cli@<version>`), falling back to `main` for 0.0.x and prerelease builds or when the tag is missing. It shares that fetch with the Starter (`withRepoCheckout` in `src/utils/starter.ts`). `NATIVECN_AGENT_KIT_DIR` points at a local folder instead (a nativecn checkout, or a folder with `rules/` and `skills/`) for development and tests. If the fetch fails (offline, firewall, no git), `agents` does not throw: it prints "Agent Kit not installed: <reason>. Retry with `npx nativecn-cli@latest agents`", skips the Rules and Skills, still writes the MCP config, permissions, components.json and Plugin hints, and returns `kit: { installed: false, error }`. The standalone command then exits with code 1; create/init carry on.

## Choices made while building #57

- **Markers.** The nativecn section of `AGENTS.md` sits between `<!-- nativecn:start -->` and `<!-- nativecn:end -->` (confirmed). Without markers the section is appended; with only one marker the file is left alone and reported.
- **"Edited".** nativecn keeps no hash of what it wrote, so any difference from the fetched section counts as edited: an interactive run shows a unified diff and asks (default: no, or yes with `--update`); `-y` keeps it; `-y --update` replaces it. The same rule covers each `.agents/skills/<name>` folder, the `nativecn-cli` MCP entry and `.codex/rules/nativecn-qa.rules`.
- **Agents.** `--agents`, else components.json `agents`, else a prompt (all four preselected), else all four. `AGENTS.md` and `.agents/skills/` are always written; `CLAUDE.md` and `.claude/skills/` (relative symlinks, copies on Windows or when symlinks fail) only for Claude. Chosen agents are added to components.json `agents` (never removed). init/create pass their own choice and skip the Agent Kit for `--agents none`.
- **MCP.** Server `nativecn-cli`, local stdio `npx -y nativecn-cli@latest mcp` (#19), merged into `.mcp.json`, `.cursor/mcp.json`, `.agents/mcp_config.json` (JSON, comments kept) and `.codex/config.toml` (`[mcp_servers.nativecn-cli]` table). Other servers are never touched. A remote entry would use `serverUrl` for Antigravity.
- **`--qa-permissions`.** Allow rules only (no `ask`/`deny`), following #34's command forms: no `-s`, `booted`, `-p <package>` deep links pinned by scheme, and save → pull → delete via `/sdcard/nativecn-qa.png` with an exact `adb shell rm /sdcard/nativecn-qa.png` rule. The laptop path is left open (`adb pull /sdcard/nativecn-qa.png *`, `simctl io booted screenshot *`) because `<OS temp>` differs per machine and the files are committed. Demo mode is allowed as `am broadcast -a com.android.systemui.demo -e command *` (enter, clock, battery, notifications, exit). Rules that need `scheme`, `android.package` or `ios.bundleIdentifier` are left out when `app.json` lacks them. List-type files (`.claude/settings.json`, `.cursor/permissions.json`, `.cursor/cli.json`) only gain entries; Antigravity gets a printed snippet.
- **`<device>`** in screenshot paths is the serial from `adb devices -l` or the Simulator `udid`, even when `-s` is left out; `android` / `ios` when unknown.
